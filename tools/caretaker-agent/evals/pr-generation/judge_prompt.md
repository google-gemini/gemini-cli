### Scoring Rubrics & Grading Standards

#### 1. Functional Parity Score (0 to 3 Points)

- **Score 3 (Full Parity):** Implements identical core functionality and logic
  as the ground-truth patch; covers edge cases and unit tests.
- **Score 2 (Minor Discrepancy):** Solves primary issue path, but misses
  secondary edge cases or unit test details present in the ground-truth patch.
- **Score 1 (Partial Fix):** Modifies relevant files but fix is incomplete,
  structurally flawed, or misses key issue requirements.
- **Score 0 (Failure / Regression):** Fails to fix the issue, introduces
  syntax/runtime errors, or causes severe regressions.

#### 2. Readability & Production Readiness Score (0 to 3 Points)

- **Score 3 (Production Exemplary):** Outstanding modularity, self-documenting
  code, expressive naming, explicit typing (no untyped dicts/`any`), robust
  defensive guards, zero technical debt.
- **Score 2 (Production Acceptable):** Clean, well-structured code ready for
  merge; explicit typing on exported signatures, proper exception handling,
  minor/negligible stylistic nits.
- **Score 1 (Below Production Standard):** Functionally works but contains code
  quality debt; non-descriptive naming (`temp`, `data1`), overly complex control
  flow, untyped structures, missing null/undefined guards.
- **Score 0 (Unacceptable / Anti-Pattern):** Severe anti-patterns, dirty
  workarounds, swallowed exceptions (`except: pass`), unhandled edge cases, or
  gross style/layering violations.
